# README 이미지 빌드

프로필 README에 쓰이는 이미지(`assets/*.svg`)는 모두 이 폴더의 스크립트로 만듭니다.
README는 이 폴더를 참조하지 않으므로, 이미지를 바꿀 일이 없다면 신경 쓰지 않아도 됩니다.

## 준비

Node.js 18 이상이 필요합니다.

```bash
cd build
npm install
```

## 이미지 다시 만들기

```bash
node build.js
```

- 모든 이미지를 먼저 메모리에서 만들고 검사한 뒤, 문제가 없을 때만 `assets/`와 `README.md`를 한꺼번에 바꿉니다. 중간에 오류가 나면 두 곳 모두 실행 전 상태 그대로 남으므로, 오류 메시지대로 고친 뒤 다시 실행하면 됩니다.
- 더 이상 쓰지 않는 SVG는 `assets/`에서 자동으로 지워집니다.
- 패키지 버전이 `package-lock.json`에 고정되어 있어, 입력이 같으면 결과 파일도 매번 똑같습니다.
- 색이나 이미지 속 문구를 바꾸려면 `build.js`의 `PAL`(색), `TAGLINE`(첫 화면 문장), `THANKS`(맺음말), `STACK`(기술 스택), `HEADINGS`(섹션 제목)를 고친 뒤 다시 실행하세요.
- 본문 문장은 이미지가 아니라 글자이므로 루트의 `README.md`를 직접 고치면 됩니다.

## 대표 프로젝트 추가하기

1. `build/projects.js`를 열고 항목을 적습니다.

   ```js
   module.exports = [
     {
       name: 'mnist-classifier',                        // 제목
       url: 'https://github.com/pilwookmoon/REPO',      // 카드를 눌렀을 때 열릴 주소
       description: '손글씨 숫자를 분류하는 CNN 실습',   // 한 줄 설명
       stack: ['Python', 'TensorFlow'],                 // 사용한 기술
     },
   ];
   ```

2. `node build.js`를 실행합니다.
3. `assets/work-01-light.svg` 같은 카드 이미지가 생기고, `README.md`의 `<!-- projects:start -->`와 `<!-- projects:end -->` 사이에 카드가 자동으로 들어갑니다. 카드는 **02 기록이 있는 곳** 섹션의 두 버튼 바로 위에 나타납니다.
4. `README.md`와 `assets/`를 함께 커밋합니다.

참고

- 넓은 화면에서는 카드가 두 개씩 나란히, 좁은 화면에서는 한 줄에 하나씩 놓입니다.
- 설명은 카드 폭에 맞춰 자동으로 줄바꿈되며 최대 3줄까지 들어갑니다. 제목이나 설명이 너무 길면 빌드가 오류로 알려 주고, 이때 기존 파일은 바뀌지 않습니다.
- 목록을 다시 비우고 실행하면 카드도 README에서 사라집니다.
- 빌드 없이 넣고 싶다면 `README.md` 주석 안의 형식을 `<!-- projects:end -->` 줄 바로 아래에 붙여 쓰면 됩니다.
  - 프로젝트가 여러 개면 항목 사이에 빈 줄을 하나씩 둡니다. 빈 줄이 없으면 두 항목이 한 줄로 붙어 버립니다.
  - 두 표시 사이는 빌드할 때마다 새로 채워지므로, 손으로 쓴 내용은 반드시 그 바깥에 둡니다.
  - 이 방식에서는 링크가 GitHub 기본 파란색으로 보입니다.

## 파일 구성

| 파일 | 역할 |
|:--|:--|
| `build.js` | 모든 SVG를 만들고, 대표 프로젝트 블록을 README에 넣습니다. |
| `type.js` | 글자를 윤곽선(path)으로 바꿉니다. 보는 사람에게 글꼴이 없어도 똑같이 보입니다. |
| `deps.js` | 글꼴과 아이콘 패키지를 찾습니다. `build/node_modules`를 먼저 보고, 없으면 `README_TOOLS` 환경 변수에 적힌 폴더를 봅니다. |
| `projects.js` | 대표 프로젝트 목록입니다. |

## 알아 두면 좋은 점

- 외부 이미지 서비스는 쓰지 않습니다. 모든 이미지는 `assets/` 안의 SVG이고, 밝은 테마용(`-light`)과 어두운 테마용(`-dark`)이 한 쌍입니다.
- 첫 화면, 기술 스택, 맺음말, 프로젝트 카드는 표시되는 폭에 따라 글자 크기를 단계별로 바꾸도록 만들어져 있어, 휴대폰에서도 글자가 지나치게 작아지지 않습니다.
- 밝은 테마용 이미지의 글자에는 흰색의 얇은 외곽선이 깔려 있습니다. GitHub의 밝은 테마는 모두 배경이 흰색이라 평소에는 보이지 않고, 혹시 어두운 화면에 밝은 쪽 이미지가 표시되더라도 글자를 읽을 수 있게 해 줍니다. 어두운 테마는 배경색이 테마마다 달라(기본, Dimmed, 고대비) 외곽선을 넣지 않았습니다.
- 글꼴: Pretendard, Instrument Serif(모두 SIL Open Font License). 아이콘: Simple Icons(CC0), MySQL 돌고래만 Devicon(MIT).
- `node_modules/`는 커밋하지 않아도 됩니다.
